# FrontFinder (fronts)

## Goal
FrontFinder finds weather fronts in ERA5 reanalysis with a UNet3+ neural network. It is an updated version of NOAA's FrontFinder (created by Andrew Justin, updated by Taylor Mandelbaum). Each grid point is labelled with one of nine classes: no front, cold, warm, stationary, occluded, dryline, trough, tropical trough, instability axis. Used by Taylor for research and for the live site at fronts.espr.ai.

## Stack
- Language/framework: Python, TensorFlow 2.16+ / Keras 3; typed with `pyrefly`, linted and formatted with `ruff`.
- Environments: `pixi` (HPC, glibc 2.17 on OU Sooner; lock in `pixi.lock`) and `uv` (dev/CI; lock in `uv.lock`). Keep both locks in sync (CI checks them).
- Data: ERA5 in Icechunk/zarr stores, generated by `fronts.data.generate`; all runs are driven by one YAML in `configs/`. Weights (`v2.0.0.keras`) live on Hugging Face (`aaaTman/FrontFinder`).
- Compute: training/eval/data generation run on OU Sooner/Schooner (GPU, Slurm; see `scripts/*.sbatch`). Unit tests and lint run locally with no GPU.

## Commands
- Setup: `just setup` (uv dev env) or `pixi install` (HPC env)
- Test: `just test`
- Lint: `just lint` (ruff check, ruff format --check, pyrefly)
- Data: `just generate`
- Train: `just train` / eval: `just eval`
- Deploy: `just deploy` (stub; deploy goes through CI, see Do not)

## Conventions
- Python style: ruff-formatted, fully typed (pyrefly clean), short docstrings. Pre-commit runs ruff and pyrefly.
- Config over flags: change behaviour through YAML in `configs/`, version configs with the code.
- Branching: one worktree per task, PRs into `master`, CI (`ci.yml`, `tests.yml`, `check-locks.yml`) must pass.
- Never commit data, keys, or model weights.

## Do not
- Edit `uv.lock` / `pixi.lock` by hand.
- Touch the live production app (LXC 108 `frontfinder`, /srv/frontfinder-app): it is a separate repo with its own rules; never run a plain `uv sync` or `pkill caddy` there.
- Deploy directly; open a PR and let CI gate it.
